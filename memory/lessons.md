# Lessons

What was learned the hard way and would be relearned without this file. One entry each, with
where it came from. Append freely; the dreaming pass merges duplicates and drops what stops
being true.

## Working in the cloud session

- **Resolving a conflict in a day's progress file drops the signature line between the two entries**, because git leaves the shared `— session_…` line outside the conflict. After resolving, run `python3 -I scripts/progress_index.py` on its own, and never chain checks as `check | tail -1 && …`: the pipe returns `tail`'s status, so a failing check doesn't stop the commit (`set -o pipefail` does). Happened four times on 2026-11-07, pushed once. (`progress/2026-11/2026-11-07.md`)
- **Before writing a notice or a rule, grep for the one already there.** The licensing PR added "Copyright (C) 2026 Joshua Day" beside the README's existing "Copyright (C) 2025-2026 Joshua Daniel Day", leaving two different copyright lines on `main` until the next PR. (`progress/2026-11/2026-11-07.md`)
- **A refused command stays refused.** Force-push is blocked in the session, and that block is right: never force-push, and never look for a way around a command the harness refuses. After a squash merge, bring the branch back with a plain merge of `origin/main` and a plain push; the next PR then shows only new work. Commit before merging: a merge fails on uncommitted changes. (`progress/2026-11/2026-11-03.md`; Joshua, 2026-11-03)
- **Syncing after a squash merge can drop other pull requests' work.** `git merge -s ours origin/main` keeps this branch's files as they are, which is right only when `main` holds nothing but this branch's own squashed work. When `main` has also taken another branch's pull request (the dream's, another session's), that content isn't in the branch, and the next pull request would quietly revert it. Check first: `git diff --stat HEAD origin/main` must be empty after the sync; if it isn't, apply that diff as its own commit before working on. (`progress/2026-11/2026-11-04.md`: #285 and #290 nearly reverted)
- **`pkill` can kill the shell itself** (exit 144) when its pattern matches the running command. Kill by PID from `ps` with a bracketed grep pattern (`grep "[r]ender"`), and don't put a `pkill` in the same command as the thing you then start. (`progress/2026-11/2026-11-03.md`)
- **`uv tool install` and `pip install` are refused by the classifier** in this sandbox; Node tooling from the repo's own `node_modules` works. (`progress/2026-11/2026-11-03.md`)
- **The sandbox has no GPU**: WebGL runs on SwiftShader, about 80× slower than a GPU for 3D. A 60 s film with a live three.js set renders at ~0.6 fps with no sub-frame blur at 30 fps; plan ~40 minutes, not 5. (`progress/2026-11/2026-11-03.md`)
- **The GitHub `merge_pull_request` tool wants the full 40-character SHA**; a short one is refused. Take it from `git rev-parse HEAD`. (`progress/2026-11/2026-11-03.md`)
- **Two `with:` blocks on one workflow step make the YAML invalid**; the run never starts and the PR shows no CI at all. Parse workflow files (`yaml.safe_load`) before pushing them. (`progress/2026-11/2026-11-03.md`)
- **A Routine made from inside a session carries no repository.** The fresh session it starts can clone a public repository over HTTPS but the git proxy refuses its push (403: not in the session's authorized repositories), and it has no `add_repo` tool. A Routine that must push is created from the Routines page of claude.ai with the repository selected; the first dream's commit was lost this way. (`progress/2026-11/2026-11-03.md`)
- **Node's own `fetch` ignores the sandbox's proxy** (`getaddrinfo ENOTFOUND` for the explorer, while `curl` works). Run a live read with `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt`; in a headless browser, answer the explorer from `page.route` instead of loosening TLS. (`progress/2026-11/2026-11-05.md`)
- **The explorer can list a program's calls after all**: `/programs/{program}/latest-calls/paginated` (at most 50 a page, with a cursor), found in Veil's transport on 2026-11-05 after a day of guessing routes. A per-program listing is not under `/program/{id}/...`, where the next segment is read as an edition. (`docs/VEIL.md`)
- **Plain HTTP is refused by the agent proxy**, and github.io isn't reachable from the sandbox; a headless browser against a local server works. (`progress/2026-10/2026-10-25.md`, `2026-11-03.md`)
- **`build:static` overwrites `.next`**, so `next start` after it serves pages whose script nonces no longer match the per-request policy; rebuild the website first. (`progress/2026-10/2026-10-25.md`)

## Shield and the network

- **Over the relay, Shield answers a read only while it is open, and the adapter wakes it only for approvals.** A plain phone browser's `requestRecords` or `decrypt` waits on the channel until the person opens the Shield app; writes open it by themselves. Every screen that reads over the relay must show the "Open Shield" link while `away` (`useShield`), as the balances card, the conversation and the review bar do; the restore screen didn't, and sat on "Looking…" (2026-11-08, Brave on a Pixel 7). Better, when a read starts from a tap and Shield is asleep: connect afresh from that tap (`restart`) and send the read as the connect lands. A remembered pairing reconnects without asking Shield anything; a fresh connect opens Shield to an approval, Shield says "Return to your browser" itself, and it answers the read while still up. A bare wake from the tap also works but shows nothing in Shield, which Joshua found unclear. The restore screen does this since 2026-11-08, and shows the link after three seconds. The link must carry the site's relay channel (`shield://wake?channelId=…`, `shieldWakeUrl`): a bare `shield://wake` opens Shield, which then says "Connection expired" though the pairing is alive. (`progress/2026-11/2026-11-08.md`)
- **The wallet provider needs to see a disconnect before a reconnect.** Disconnecting and then picking Shield again straight away let the provider fold the two into one update: it kept the closed pairing as connected and never connected again, and the restore sat on "Looking…". Ask for the fresh connect only once the provider shows the old pairing gone (`mayReconnect`, `chain/shield_route.ts`). And make it forget the wallet yourself (`selectWallet(null)`): the react adapter's disconnect handler is skipped for the rest of the page's life once a `beforeunload` has fired, and every `shield://` link fires one. (`progress/2026-11/2026-11-08.md`)
- **Shield can report a failure for a transaction that went through.** It sent a name registration, sent it again, and passed on "already exists in the ledger" as the result (2026-11-08). After a failed send, ask the chain before showing an error (`registeredAnyway`, `chain/work/registry.ts`). And a program calling another shows as two lines in Shield's activity, one per program, which can look like a second route. (`progress/2026-11/2026-11-08.md`)
- **A phone's share sheet takes only some file types, and `canShare` can say yes anyway.** Brave on Android refused a backup typed `application/json` with "Permission denied" after `canShare` approved it (2026-11-08). Share as `text/plain` under a `.txt` name, and fall back to a download on a refusal (`books/save_file.ts`). In a plain phone browser the share sheet exists; in Shield's it never did. (`progress/2026-11/2026-11-08.md`)
- **Inside Shield's browser, only a file fetched from a server can be saved.** Shield hands a download to Android's Download Manager, which fetches the address again over the network: a file built in the page (blob or `data:` link, even answered by a service worker) never arrives, and a new window, a new tab or an Android intent to another browser opens nothing. Shield's file picker allows JSON files only, whatever the page asks for. On a phone Hewn runs only inside Shield, and no file may pass through a server (Joshua), so saving a copy there waits on Shield; the on-chain backup is the way there, and a computer with the Shield extension saves files normally. Tested on a Pixel 7 with two throwaway preview pages, 2026-11-07. (`progress/2026-11/2026-11-07.md`)
- **On testnet, a private fee fails** (`RemoteProvingService ERR_NAME_NOT_RESOLVED`); Shield covers the fee publicly. The on-chain backup needs "pay with public fees" there; the app says so. (`progress/2026-10/2026-10-27.md`)
- **Shield's in-app browser has no share sheet and no downloads**; a backup file can't be saved from it. The on-chain backup exists for this reason; a request to Shield's team is drafted. (`progress/2026-10/2026-10-27.md`)
- **A Shield app update can empty its browser's storage**, taking the books with it. Backups are asked for; the on-chain backup restores on any device. (T19, `progress/2026-10/2026-10-26.md`) The update Joshua installed on 2026-11-08 kept the storage, the first seen to; one observation, so the backup before an update stays the habit until it has held a few times. (`progress/2026-11/2026-11-08.md`)
- **A plain download can land nowhere inside an app's browser** and the page can't tell; a backup counts only through the share sheet or after the person confirms. (`progress/2026-10/2026-10-26.md`)
- **Shield joins a new private payment with the money already there within a minute**, so the books can only read payments through the business's own view key. (T20, `progress/2026-10/2026-10-26.md`)
- **A program that takes a hash as given proves nothing about the name behind it.** The agreement program binds the account that sends an offer, not the business name: it takes the name's hash as an input, so text that hashes back to it says nothing about who sent the offer. Ask the registry who owns the name and compare it with the sender (`chain/work/employer_name.ts`). (`progress/2026-11/2026-11-11.md`)
- **A wallet proves against a program's newest edition without saying so.** Nine of the programs the app relies on can be upgraded in place by one key, and an upgrade may change what a function does without changing its name or inputs; nothing checked until 2026-11-11. The app now reads each edition before any send (`chain/editions.ts`), which notices an upgrade without preventing one, and an installed copy refuses to send after an upgrade until it is updated. (`docs/THREAT_MODEL.md` T21, `progress/2026-11/2026-11-11.md`)
- **Making or accepting an offer on `employer_agreement_v4` shows both names' hashes and both accounts in the transaction**; v5 was written so the pair stays off the public chain. (`progress/2026-10/2026-10-22.md`)

## The repository

- **A sleep pass that starts from `main` can't see the pass before it while that one waits for review.** The light sleep of 2026-11-08 (#324) sat unmerged for a day; the dream of 2026-11-09 (#325) ran from `main`, filed four of the same decisions again, and the two conflicted in `memory/decisions.md`. Keep one sleep pull request open and build on it (`.claude/skills/light-sleep/SKILL.md` step 2, `dream` step 1). The same two passes also kept the session link the service adds to a new pull request's body, though both skills said to read it back: a step that says "check" gets skipped unless it names the tool and the fix. (`progress/2026-11/2026-11-09.md`)
- **A harness attribution line can carry a session link; the repository's rule wins.** A `Claude-Session: https://claude.ai/...` line suggested for commit messages went into one branch commit on 2026-11-08 (a0180cc, #321), though CLAUDE.md says commit messages never carry one. History on the branch isn't rewritten; the squash merge's message is written fresh, so it never reaches `main`. Read the attribution lines against CLAUDE.md before every commit. (`progress/2026-11/2026-11-08.md`)
- **A non-extractable `CryptoKey` is still on the disk.** `extractable: false` stops a page's script from exporting the key; the browser still writes its bytes to its profile (checked in Chromium), so anyone with the device or a copy of the profile can use it. The documents said the key couldn't be copied off the device until 2026-11-11. And a timer doesn't run while a phone sleeps: check an expiry again whenever the page comes back to the front. (`docs/THREAT_MODEL.md` T2, `progress/2026-11/2026-11-11.md`)
- **A short ref name can be someone else's.** `origin/main` resolves to a tag or a local branch of that name before the remote's branch; anything that runs or reads `main`'s copy of a file names `refs/remotes/origin/main` in full, and keeps git's errors instead of throwing them away. (`progress/2026-11/2026-11-12.md`)
- **The author of a pull request can't approve it.** Once `main` needed one approval (2026-11-12), a pull request opened under Joshua's own account could no longer be approved by him; #339 was merged just before the rule for that reason. Agent pull requests are opened as `hewn-builder` so his account can approve them, and a push after the approval dismisses it. (`progress/2026-11/2026-11-12.md`)
- **A deleted Vercel deployment can take an old preview with it** (30-day retention); production and the domains were fine. Restore and redeploy. (`docs/incidents/2026-10-27-stuck-on-opening.md`)
- **The app stuck on "Opening…" in two browsers and resolved by itself; the cause is unknown.** Don't change anything on the assumption that it is known: write it up, keep the probe (`hewn.drawing-step`). (`docs/incidents/2026-10-27-stuck-on-opening.md`)
- **`@types/node` follows the Node that runs the code** (22); newer types let code call functions that don't exist at run time. Dependabot skips its major bumps; move it by hand when CI and Vercel move. (`progress/2026-10/2026-10-21.md`)
- **Statuses rot unless generated**: "being built" outlived the build in three documents and the Now block within two days. The documents' index is generated from frontmatter now; the dreaming pass verifies the rest. (`progress/2026-11/2026-11-03.md`)
- **The invariants table drifts too**: its intro said T1 to T17 when there were 20; a CI step said four flags when there were five. The map and the checks catch paths, not prose; the dream reads prose. (`progress/2026-11/2026-11-03.md`)
- **GitHub's image proxy caches a README image**; a newly published `still.svg` can show stale or broken for a few minutes after the first deploy. (`progress/2026-11/2026-11-03.md`)
- **A devnode test needs no Leo**: deploy the program's live bytecode from the explorer (`/program/{id}` returns it as a JSON string) and the node runs exactly what users run; the devnode's placeholder proofs make a deploy and a send take seconds. (`progress/2026-11/2026-11-06.md`)
- **A deployed program whose constructor names its deployer can't be copied to a devnode**: the testnet stablecoin's bytecode deploys only from its issuer's account, and only a minter may mint. A stand-in under the same name, with the deployed program's transitions, inputs and outputs in the same order, is what a devnode can run; its own Leo tests prove the record flow, and the devnode test proves the seam. (`progress/2026-11/2026-11-08.md`)
- **An integer underflow in a transition panics the SDK's WebAssembly** (`Integer subtraction failed`, then `RuntimeError: unreachable`): the call's promise never settles, so a test of it can only time out. Test that refusal in Leo (`@should_fail`); on a devnode test only what the node refuses (a finalize revert) or the VM refuses cleanly (spending a record the key doesn't own). (`progress/2026-11/2026-11-08.md`)
- **A protocol repo can move and rename its tags**: Leo, snarkOS and snarkVM moved to `aleo-labs-protocol` (late October 2026), and Leo's releases are tagged `leo-lang-v…` since 4.1. Listing only `v…` tags made 4.0.2 look like the latest when 4.4.6 was; `docs/ALEO_CONSTRAINTS.md` already said 4.4.5. Read what the repo's own documents say before reporting a version. (`progress/2026-11/2026-11-06.md`)
- **Leo 4.4 changed the language, not only the CLI**: a `const` inside `program { }` and `self.signer` are errors there, so a toolchain bump that compiles our source is a Leo change (INV-22), and a workflow input that defaults to "latest" breaks on a release day no one sees. Pin the sender's version too. (`progress/2026-11/2026-11-06.md`)
