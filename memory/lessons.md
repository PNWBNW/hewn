What was learned the hard way and would be relearned without this file. One entry each, with

## Working in the cloud session

- **Resolving a conflict in a day's progress file drops the signature line between the two entries**, because git leaves the shared `— session_…` line outside the conflict. After resolving, run `python3 -I scripts/progress_index.py` on its own, and never chain checks as `check | tail -1 && …`: the pipe returns `tail`'s status, so a failing check doesn't stop the commit (`set -o pipefail` does). Happened four times on 2026-11-07, pushed once. (`progress/2026-11-07.md`)
- **Before writing a notice or a rule, grep for the one already there.** The licensing PR added "Copyright (C) 2026 Joshua Day" beside the README's existing "Copyright (C) 2025-2026 Joshua Daniel Day", leaving two different copyright lines on `main` until the next PR. (`progress/2026-11-07.md`)
- **A refused command stays refused.** Force-push is blocked in the session, and that block is right: never force-push, and never look for a way around a command the harness refuses. After a squash merge, bring the branch back with a plain merge of `origin/main` and a plain push; the next PR then shows only new work. Commit before merging: a merge fails on uncommitted changes. (`progress/2026-11-03.md`; Joshua, 2026-11-03)
- **Syncing after a squash merge can drop other pull requests' work.** `git merge -s ours origin/main` keeps this branch's files as they are, which is right only when `main` holds nothing but this branch's own squashed work. When `main` has also taken another branch's pull request (the dream's, another session's), that content isn't in the branch, and the next pull request would quietly revert it. Check first: `git diff --stat HEAD origin/main` must be empty after the sync; if it isn't, apply that diff as its own commit before working on. (`progress/2026-11-04.md`: #285 and #290 nearly reverted)
- **`pkill` can kill the shell itself** (exit 144) when its pattern matches the running command. Kill by PID from `ps` with a bracketed grep pattern (`grep "[r]ender"`), and don't put a `pkill` in the same command as the thing you then start. (`progress/2026-11-03.md`)
- **`uv tool install` and `pip install` are refused by the classifier** in this sandbox; Node tooling from the repo's own `node_modules` works. (`progress/2026-11-03.md`)
- **The sandbox has no GPU**: WebGL runs on SwiftShader, about 80× slower than a GPU for 3D. A 60 s film with a live three.js set renders at ~0.6 fps with no sub-frame blur at 30 fps; plan ~40 minutes, not 5. (`progress/2026-11-03.md`)
- **The GitHub `merge_pull_request` tool wants the full 40-character SHA**; a short one is refused. Take it from `git rev-parse HEAD`. (`progress/2026-11-03.md`)
- **Two `with:` blocks on one workflow step make the YAML invalid**; the run never starts and the PR shows no CI at all. Parse workflow files (`yaml.safe_load`) before pushing them. (`progress/2026-11-03.md`)
- **A Routine made from inside a session carries no repository.** The fresh session it starts can clone a public repository over HTTPS but the git proxy refuses its push (403: not in the session's authorized repositories), and it has no `add_repo` tool. A Routine that must push is created from the Routines page of claude.ai with the repository selected; the first dream's commit was lost this way. (`progress/2026-11-03.md`)
- **Node's own `fetch` ignores the sandbox's proxy** (`getaddrinfo ENOTFOUND` for the explorer, while `curl` works). Run a live read with `NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt`; in a headless browser, answer the explorer from `page.route` instead of loosening TLS. (`progress/2026-11-05.md`)
- **The explorer can list a program's calls after all**: `/programs/{program}/latest-calls/paginated` (at most 50 a page, with a cursor), found in Veil's transport on 2026-11-05 after a day of guessing routes. A per-program listing is not under `/program/{id}/...`, where the next segment is read as an edition. (`docs/VEIL.md`)
- **Plain HTTP is refused by the agent proxy**, and github.io isn't reachable from the sandbox; a headless browser against a local server works. (`progress/2026-10-25.md`, `2026-11-03.md`)
- **`build:static` overwrites `.next`**, so `next start` after it serves pages whose script nonces no longer match the per-request policy; rebuild the website first. (`progress/2026-10-25.md`)

## Shield and the network

- **Inside Shield's browser, only a file fetched from a server can be saved.** Shield hands a download to Android's Download Manager, which fetches the address again over the network: a file built in the page (blob or `data:` link, even answered by a service worker) never arrives, and a new window, a new tab or an Android intent to another browser opens nothing. Shield's file picker allows JSON files only, whatever the page asks for. On a phone Hewn runs only inside Shield, and no file may pass through a server (Joshua), so saving a copy there waits on Shield; the on-chain backup is the way there, and a computer with the Shield extension saves files normally. Tested on a Pixel 7 with two throwaway preview pages, 2026-11-07. (`progress/2026-11-07.md`)
- **On testnet, a private fee fails** (`RemoteProvingService ERR_NAME_NOT_RESOLVED`); Shield covers the fee publicly. The on-chain backup needs "pay with public fees" there; the app says so. (`progress/2026-10-27.md`)
- **Shield's in-app browser has no share sheet and no downloads**; a backup file can't be saved from it. The on-chain backup exists for this reason; a request to Shield's team is drafted. (`progress/2026-10-27.md`)
- **A Shield app update can empty its browser's storage**, taking the books with it. Backups are asked for; the on-chain backup restores on any device. (T19, `progress/2026-10-26.md`)
- **A plain download can land nowhere inside an app's browser** and the page can't tell; a backup counts only through the share sheet or after the person confirms. (`progress/2026-10-26.md`)
- **Shield joins a new private payment with the money already there within a minute**, so the books can only read payments through the business's own view key. (T20, `progress/2026-10-26.md`)
- **Making or accepting an offer on `employer_agreement_v4` shows both names' hashes and both accounts in the transaction**; v5 was written so the pair stays off the public chain. (`progress/2026-10-22.md`)

## The repository

- **A deleted Vercel deployment can take an old preview with it** (30-day retention); production and the domains were fine. Restore and redeploy. (`docs/incidents/2026-10-27-stuck-on-opening.md`)
- **The app stuck on "Opening…" in two browsers and resolved by itself; the cause is unknown.** Don't change anything on the assumption that it is known: write it up, keep the probe (`hewn.drawing-step`). (`docs/incidents/2026-10-27-stuck-on-opening.md`)
- **`@types/node` follows the Node that runs the code** (22); newer types let code call functions that don't exist at run time. Dependabot skips its major bumps; move it by hand when CI and Vercel move. (`progress/2026-10-21.md`)
- **Statuses rot unless generated**: "being built" outlived the build in three documents and the Now block within two days. The documents' index is generated from frontmatter now; the dreaming pass verifies the rest. (`progress/2026-11-03.md`)
- **The invariants table drifts too**: its intro said T1 to T17 when there were 20; a CI step said four flags when there were five. The map and the checks catch paths, not prose; the dream reads prose. (`progress/2026-11-03.md`)
- **GitHub's image proxy caches a README image**; a newly published `still.svg` can show stale or broken for a few minutes after the first deploy. (`progress/2026-11-03.md`)
- **A devnode test needs no Leo**: deploy the program's live bytecode from the explorer (`/program/{id}` returns it as a JSON string) and the node runs exactly what users run; the devnode's placeholder proofs make a deploy and a send take seconds. (`progress/2026-11-06.md`)
- **A protocol repo can move and rename its tags**: Leo, snarkOS and snarkVM moved to `aleo-labs-protocol` (late October 2026), and Leo's releases are tagged `leo-lang-v…` since 4.1. Listing only `v…` tags made 4.0.2 look like the latest when 4.4.6 was; `docs/ALEO_CONSTRAINTS.md` already said 4.4.5. Read what the repo's own documents say before reporting a version. (`progress/2026-11-06.md`)
- **Leo 4.4 changed the language, not only the CLI**: a `const` inside `program { }` and `self.signer` are errors there, so a toolchain bump that compiles our source is a Leo change (INV-22), and a workflow input that defaults to "latest" breaks on a release day no one sees. Pin the sender's version too. (`progress/2026-11-06.md`)
