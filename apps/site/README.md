# Marketing site

The public front page and privacy page, deployed on its own domain. It shares the brand
(`@pnw/brand`), the security headers (`@pnw/security`) and the theme tokens (`@pnw/ui`) with the
app, and nothing else: no ledger, no vault, no chain package, no analytics, no third-party scripts.

Pages: `/` (landing) and `/privacy`. Every page is rendered per request so it carries a fresh CSP
nonce (`src/proxy.ts`), like the app.

## Deploying on Vercel

A second Vercel project on the same repository:

| Setting | Value |
|---|---|
| Root directory | `apps/site` |
| Environment variable | `ENABLE_EXPERIMENTAL_COREPACK=1` (uses the pnpm pinned in the root `package.json`) |
| Environment variable (optional) | `NEXT_PUBLIC_APP_URL` — where "Open the app" points; defaults to the app's address in `packages/brand` |
| Environment variable (optional) | `NEXT_PUBLIC_SITE_URL` — this site's own address, for link previews; defaults to the site's address in `packages/brand` |

Framework preset Next.js, build and install commands left at their defaults. Attach the apex domain
and `www`.

## Brand assets

`public/brand/` and `src/app/{icon.png,apple-icon.png,favicon.ico}` are generated by
`brand/build_assets.py` (the same files the app serves). Never edit them by hand; re-run the script.

## Locally

```sh
pnpm --filter @pnw/site dev     # http://localhost:3000
pnpm --filter @pnw/site build && pnpm --filter @pnw/site start
pnpm --filter @pnw/site test    # boundary and policy checks
```
