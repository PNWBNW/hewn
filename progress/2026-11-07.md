## 2026-11-07 — Sleep: the design document

Joshua read Google Research's sleep framework for continual learning (Behrouz and Mirrokni,
2026-10-27; the paper, arXiv 2606.03979) and asked how it applies to Hewn's agents and to Claude
Code itself. Read from the sources (the blog and the paper's §2.2 to §3.4; `research.google` and
`arxiv.org` added to the environment's allowed hosts for it) and the Claude Code documentation
for the hooks and skills it would take. `docs/SLEEP.md`, extending `docs/MEMORY.md`:

- What Hewn called dreaming is the paper's consolidation; the paper's dreaming (REM) is what Hewn
  lacked. Three additions: consolidate before compaction (a `PreCompact` hook whose output
  instructs the summary and a `SessionStart` `compact` hook that reads the state back), the
  missing slow rung with promotion and pruning between `memory/` and the rules, and a monthly REM
  pass (random pairs of the repository, adversarial tests and questions, keep only what finds
  something, a pull request of findings and never fixes).
- Three rhythms (Joshua): every compaction, nightly light sleep, weekly dream; REM monthly. A pass
  runs regardless; one with nothing to do ends with "Nothing needed" in the Routine's run history
  and writes nothing. Every change is still a pull request Joshua approves.
- The pieces as a plugin usable in any repository: `wake` and `consolidate` hooks, `/rest`,
  `/dream`, `/light-sleep`, `/rem` skills (`context: fork`, model invocation off for the passes).
  Two limits from the documentation: repository hooks apply in local and single-repository cloud
  sessions (this one has three repositories attached, so it consolidates by hand), and auto
  memory is machine-local, which is why memory lives in the repository.
- The order: this document; the two hooks; `/rest` and `/dream` with the nightly pass; `/rem`
  first by hand; the plugin. The decision in the ledger; `docs/MEMORY.md` points here.

## 2026-11-07 — Sleep step 2: consolidate before compaction, wake after it

- `consolidate` on `PreCompact`: writes the mechanical state (branch and HEAD, dirty files,

- Tried live in this worktree: both outputs are right. The first run inside a real compaction
  waits for a local or single-repository session (this one has three repositories attached, so

## 2026-11-07 — Licensing: copyright notice, the attribution term, the commercial licence

Joshua asked whether someone could take Hewn, change it, close it up and sell it without saying
where it came from, and whether the licence should get stricter before mainnet. Under AGPL-3.0

Decision: stay on AGPL (the strictest licence that is still open source; the grant proposal
promises it; the positioning relies on it) and tighten around it. What this PR does:

- `NOTICE`: Copyright (C) 2026 Joshua Day, personally; the AGPL with one additional term; the
  commercial licence; Hewn™ a trademark of Joshua Day.
- `LICENSING.md`: the open licence in short; the section 7(b)
  term (every copy keeps "Hewn by Joshua Day", linked to the repository, where its users see it;
  "Based on" may go in front, nothing may be removed); the commercial licence for a closed or
  proprietary product, from hewnsupport@gmail.com, the Leo programs included; the name; and
  contributions under a contributor licence agreement, still to be written (its own PR).
- `CREDIT` in `packages/brand/src/index.ts`, beside `BRAND`: the one line a fork never changes.
  The app's small print (`LegalLinks`, on the front page and the rail) and the site's footer show
  it.
- README's licence section and CONTRIBUTING's Forking section say the same in short.

Two gaps closed on Joshua's "no wiggle room": a work with no user interface keeps the attribution in its documentation and `NOTICE`; and rights beyond the AGPL come only from a written licence agreement signed by Joshua Day, never an email, a payment or the file itself. The attribution term stays worded as section 7(b) allows (author attributions in the Appropriate Legal Notices), since a term reaching further could be stripped as a "further restriction" under section 7. The published texts carry no "draft" label (Joshua, 2026-11-07: a label would invite the argument that the terms weren't final); if a lawyer's review changes the wording, the new version is published and git records which version a copy was taken under.

contributor agreement; the USPTO filing for "Hewn" (an individual can file, intent-to-use,
classes 9 and 42); optional copyright registration, which asks for AI-written parts to be
disclosed and claims the human-authored part. None of it needs a business licence; a local one
