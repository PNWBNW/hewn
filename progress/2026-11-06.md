## 2026-11-06 — Veil step 1: letters against a real Aleo node, in tests and CI

Joshua's go-ahead ("start step 1", `docs/VEIL.md`). Hewn's chain code had only ever met the
deployed programs on testnet, by hand; now one test runs it against the real program on a local
node, in CI.

- **The test** (`apps/business/test/devnode/letters.devnode.test.ts`, its own vitest config,
  outside `pnpm test`): starts a devnode, deploys `hewn_letters_v2` from its live bytecode
  (`test/devnode/programs/`, read from the explorer, sha256 checked before the deploy), and drives
  it with Hewn's own `letterCall`, `manyCalls`, `parseLetterRecord` and the mailbox's `seal` and
  `open`. Five cases: the file is the program Hewn sends with; a letter only its recipient opens,
  with the sender's copy, and a stranger opens nothing; a long document goes as a page; one
  announcement to three people in one `send_many`, padded with the sender (who gets six records
  back); and an all-zero lookup the program refuses.
- **The packages**, development dependencies of the app only: `@provablehq/veil-core`,
  `veil-aleo-sdk`, `veil-aleo-devnode` 0.15.0 (2026-10-29, the newest at least seven days old,
  OPS-04) and `@provablehq/aleo-devnode` 0.4.0 (the node binary, per platform). `veil-aleo-sdk`
  brings `@provablehq/sdk` 0.13.0 nested; the app still resolves 0.10.1.
- **The signing path**: `scripts/check_signing_path.py` rule 7 refuses an import of
  `veil-aleo-sdk`, `veil-aleo-devnode`, `veil-leo` or `aleo-devnode` outside tests, since they sign
  with a local key (checked with a probe file: FAIL, then PASS without it). INV-11's row says so.
- **CI**: a step after the tests, `pnpm --filter @pnw/business test:devnode`.
- **Docs**: `test/devnode/README.md` (how it works, the key, refreshing the bytecode); the app's
