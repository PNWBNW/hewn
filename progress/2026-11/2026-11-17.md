## 2026-11-17 — No script from someone else's dashboard, written into the threat model with a test

**What happened.** Joshua asked whether Hewn could be hit by code pushed through a tag or A/B
testing service, the way Optimizely Web's custom project JavaScript runs whatever its dashboard
holds on every page. It can't: no such service is in either app, the security policy names no
script host, and only scripts from the site that carry the page's nonce run. He asked for it to be
a rule.

**What changed.**
- `docs/THREAT_MODEL.md` T3: no script whose code is controlled from someone else's dashboard,
  ever. Vercel Web Analytics stays the one script from outside: it is served from the site's own
  address by the host that already serves every file, so it trusts Vercel with nothing new.
- T3 said `dangerouslySetInnerHTML` was not used; it is, in four places, each HTML the app built
  and escaped itself (the three card drawings and the paper page). The line now says so.
- `apps/business/src/security/no_remote_scripts.test.ts`: the app's third-party runtime packages
  are a fixed list; no page adds a script or iframe tag, an external `.js` source or `next/script`;
  `script-src` names no host on the website or in the static bundle; raw HTML only in those four
  files. A planted Optimizely snippet and a planted fifth raw-HTML file each fail it. The
  marketing site already had the same guard (`apps/site/src/site_boundary.test.ts`).

**Tests.** The business app: 129 files, 1,086 tests pass (the security folder: 3 files, 18). The invariants check, docs index
and link check pass.

**Open.** This container can't reach hewnaccounting.com, so the live headers weren't read from
here.
