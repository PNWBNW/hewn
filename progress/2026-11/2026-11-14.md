## 2026-11-14 — The wallet asks Shield for every program the app calls

**What happened.** Joshua made a business account and the card step of setup failed in the Shield
extension (1.46.0) with Shield's own words: "hewn_cards_v1.aleo is not in the allowed programs,
request it when connect".

**Why.** The list of programs the app asks Shield to allow at connect (`WALLET_PROGRAMS`,
`packages/wallet/src/wallet-provider.tsx`) had 19 ids and the config has 24: it lacked
`employer_agreement_v5.aleo`, `hewn_cards_v1.aleo`, `hewn_credentials_v1.aleo`, `merkle_tree.aleo`
and `test_usdcx_multisig_core.aleo`. Each joined `@pnw/config` when it was deployed or pinned and
never joined this list, and nothing checked the two against each other. Offers on v5 and
credentials went through from the site in late October with the same list, so Shield did not
refuse an unlisted program then; the extension does now. Which Shield version began to, and
whether its phone app does too, is not known here.

**What changed.**
- `WALLET_PROGRAMS` gains the five, each after what it imports. Still one module constant: the
  React provider disconnects whenever its `programs` array changes identity.
- `packages/wallet/src/wallet-provider.test.ts`: the list equals `credits.aleo` plus every id in
  the config's groups but `legacy` (read through the explorer only); each id once; a program
  after its imports; one array identity. The first of these failed on the old list. A program
  added to the config and not to the list now fails the suite.
- A connection made before a program joined the list keeps its old grant. `useShield()`'s
  `executeTransaction` now turns Shield's refusal into what to do (`notAllowedProgramHint` in
  `apps/business/src/chain/shield_route.ts`): disconnect this site in Shield, connect again, try
  once more; nothing was sent. Other errors pass through unchanged.

**For people already connected.** After this ships, the extension keeps the old grant until the
site is disconnected in Shield and connected again. Over the phone relay the remembered pairing
is keyed on the list, so the app asks for one fresh pairing by itself.

**Checks.** `pnpm test`: 177 files, 1,494 tests pass (6 new). Secrets, links, invariants,
signing-path and program-names checks pass. No screen, no Leo program and no rule changed.

**Open.** Not yet seen on a device: the card step succeeding after a reconnect, and whether
reads of v5 offers and credentials (`requestRecords`) were also being refused for an account
connected with the old list. The merge needs `[deploy]` to reach the site.
