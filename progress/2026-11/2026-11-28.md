## 2026-11-28 — A three-layer pair key: P-256, ML-KEM-1024 and an optional shared secret, not wired yet

Joshua's go in session (2026-11-28): a conversation's pair key moves from P-256 alone to three
layers (`docs/NATIVE_HARDENING.md` section 7, on its branch). This is the first of a series: the
cryptographic core and its tests only, in a new package, `packages/pair-keys` (`@pnw/pair-keys`,
layer 2: it takes only the word list from `vault`). Nothing in the app calls it; every pair stays
version 1, made as before.

- **The format, version 2** (`src/format.ts`): a version byte, then parts tagged by algorithm,
  each once, ascending: `0x01` P-256 (the point), `0x02` ML-KEM-1024 (the encapsulation key, or
  the ciphertext), `0x03` HQC reserved and refused until its standard is final; an unknown id is
  refused by number. A version 1 half (the bare point, `0x04`) is told apart by its first byte. A
  half is 1,641 bytes, the answer 3,214: both fit one page, not a letter.
- **Who encapsulates:** the responder, to the initiator's ML-KEM key, which it holds when it
  answers; the ciphertext rides back with the answer, so the handshake stays two messages.
- **The combiner:** HKDF-SHA256, salt the agreement's parties key (as version 1); every secret in
  the extract step, the whole transcript (both halves in their roles, the ciphertexts, the
  version, whether the third layer is used) in the info. Chosen over X-Wing's SHA3-256 combiner,
  whose proof is for X25519 with ML-KEM-768 and leaves the ciphertext out for that pairing.
- **The out-of-band secret** (`src/out_of_band.ts`): 32 to 64 bytes, shorter refused (the plan
  says 128 bits; this work set 256); made as 32 random bytes; written as 26 BIP-39 words (the
  vault's pinned list, now exported as `@pnw/vault/passphrase-words`) or a `PNW-OOB1:` code of 58
  base32 characters for a QR code. An 8-bit hash and two Reed–Solomon symbols over GF(2¹¹): one
  or two wrong words, two swapped, or one wrong character of the code is always caught.
- **The dependency:** `@noble/post-quantum` 0.7.1, published 2026-08-27 (93 days old, the newest
  release), MIT, its three dependencies already locked at 2.4.0. Its README says it is
  self-audited (0.6.1), not independently audited, and not constant-time; it is checked here
  against NIST's ACVP vectors for ML-KEM-1024 (ACVP-Server `975de31e`).
- **Fixtures for the Rust port:** `fixtures/pair_keys_v2.json` (fixed test inputs, each layer's
  secret, the combiner's input, the info's hash, the key; and version 1's), checked both by the
  package and by the construction written out by hand. `apps/business/src/chain/key_ring.test.ts`
  now pins the app's own version 1 `pairKeyHex` to that file's version 1 answer.
- Docs: the package's README (the layers, the format, the HQC slot, the combiner and why), its row
  in `packages/README.md`, the map's Vault region, the decision in the ledger, the Now block.
