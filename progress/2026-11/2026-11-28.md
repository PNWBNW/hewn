## 2026-11-28 — HQC-5 from the HQC team's v5.1.0 reference, compiled to WebAssembly, checked on the 100 official vectors

Joshua's "option A" (in session): no npm package implements the current HQC specification under an
allowed licence and age, so HQC-5 comes from the HQC team's own reference code, vendored and
compiled to WebAssembly here. A new package, `packages/hqc` (`@pnw/hqc`, layer 0, no dependency);
nothing in the app or in `packages/pair-keys` calls it yet.

- **Provenance:** gitlab.com/pqc-hqc/hqc, tag `v5.1.0` (tag object `bd3ed177`, tagged 2026-10-26
  14:12 UTC), commit `06567ccbad10580d78dd7863b15d23f41076d57f`; public domain. Vendored: the
  reference (`src/ref`), `src/common` and `lib/fips202` for HQC-5, 28 files and the licence, at
  their own paths; the official `kats/ref/hqc-5/PQCkemKAT_32.rsp` (100 vectors, SHA-256
  `e5066df4…5edb`, as expected). `vendor/manifest.json` holds every file's SHA-256;
  `scripts/check_vendor.py` checks it offline (`ci.yml`) and, with `--upstream`, against
  gitlab.com at the pinned commit (`hqc.yml`); its tests 15 passed. Upstream agrees today.
- **One patch, for review:** `src/ref/hqc-5/parameters.h`, `BITMASK`'s `1UL` → `1ULL`. For HQC-5
  the mask shifts by 37; an `unsigned long` is 32 bits on wasm32, so the shift is undefined and,
  built unpatched, 0 of the first 3 vectors came out right (wrong public keys, so everything after).
  With `1ULL` the value is unchanged on 64-bit systems. The manifest records upstream's hash, the
  replacement and why, and the check undoes it to find upstream's file, so no other change can hide
  in that file. Worth reporting to the HQC team; Joshua's call. Two files of ours beside it: an
  empty `immintrin.h` (three reference headers include it and use nothing from it) and
  `wasm/hqc5.c`, the reference's `randombytes()` fed from the JavaScript side, and the exports.
- **Toolchain:** wasi-sdk's GitHub releases couldn't be reached from this session's sandbox, so the
  pin is Ubuntu 24.04's own packages of LLVM 18.1.3 (`clang-18`, `libclang-cpp18`, `libllvm18`,
  `libclang-common-18-dev`, `lld-18`, `1:18.1.3-1`) and wasi-libc (`0.0~git20230113.4362b18-3`),
  each with its address, size and SHA-256 (`wasm/toolchain.json`), the hashes matching noble's
  signed `InRelease` (good signature from the 2018 archive key, checked here with `gpgv`). All are
  long past seven days. `scripts/build_wasm.py` checks each before unpacking it, links only
  `memcpy.o` and `memset.o` of the C library, and reads the module back.
- **The module:** `dist/hqc5.wasm`, 34,504 bytes, SHA-256
  `edf6c5fb5b134a7b1048a450e65a517cf17241f1c9392bd01c5ee6f3cb51db55`; imports nothing; exports
  its memory, `hqc5_keygen`, `hqc5_encaps`, `hqc5_decaps` and `hqc5_layout`; a fixed 640 KiB memory,
  the stack first (512 KiB; decapsulation uses 205 KiB). **Reproducible:** three builds here (two
  from the cache, one from fresh downloads, each in a new folder) gave the same bytes, and so did
  the first run of the new `.github/workflows/hqc.yml` on GitHub's `ubuntu-24.04` runner (#401),
  which rebuilds it on every pull request that touches the package (contents: read, no secret) and
  fails on any difference.
- **The wrapper** (`src/index.ts`, `src/module.ts`): `keygen(seed)`, `encapsulate(publicKey,
  random?)`, `decapsulate(secretKey, cipherText)`, `isHqc5PublicKey`, the sizes (7,237, 32,
  14,421, 32), `IMPLEMENTATION` = "HQC-5, specification v5.1, reference v5.1.0 of 2026-10-26" for
  the pair-key id `0x03`. The bytes ride in the package as base64 and are instantiated with an
  empty import object; every buffer and the whole stack are zeroed after each call, and a trap
  drops the instance. In Node: key generation 13 ms, encapsulation 27, decapsulation 52.
- Docs: the package's README (provenance, the patch, the toolchain, how to rebuild and check, the
  caveats: reference code, no constant-time guarantee in WebAssembly or JavaScript, which matters
  little with one ciphertext per key and no oracle; HQC's standard not final), its row in
  `packages/README.md`, the checks in the OPS-04 row of `docs/INVARIANTS.md`, the decision in the
  ledger.
