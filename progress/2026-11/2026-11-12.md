## 2026-11-12 — Signing runs in two jobs; the session hooks name main in full

From the second pass of the security review.

In `pnw_mvp_v2` (#236, merged): the deploy and upgrade workflows have a build job with no key,
which compiles the program and writes a summary to approve (the bytecode's SHA-256, and for an
upgrade every line that changes against the edition on chain), and a sign job that gets the key
after approval and checks it holds that bytecode. Sending needs the SHA-256 from a check-only run.
Both Leos are release downloads checked against a SHA-256 in the workflow, and the endpoint is
fixed. The checksum workflow takes its URLs as variables and only release assets. The plan gate's
token is read-only. The submodule here moves to it.

Here:

- `.claude/settings.json`: the hooks read the snapshot script from `refs/remotes/origin/main`, the
  full name, so a tag or a local branch called `origin/main` can't stand in for it, and git's
  errors are no longer thrown away. The skills and the Routines' prompts in
  `.claude/skills/README.md` use the full name the same way.
- `scripts/sleep/snapshot.py`: a file, branch, worktree or note name reaches the snapshot only when
  it is a plain name (no spaces, at most 100 characters); the snapshot is never written through a
  symlink.
- `docs/SLEEP.md` and `scripts/sleep/README.md` say so, and what a repository can't cover: the hook
  commands are read from the checked-out settings file, so an outside branch is read as a diff,
  never checked out in the project folder.
- `BUILD_PLAN.md`: exploring a multisig goes on the mainnet list (Joshua).

The three Routines on claude.ai still carry the short name in their own prompts; they change on
the Routines page.
