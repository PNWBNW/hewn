## 2026-11-25 — Pairing with Shield on a phone moves to Shield's verified link, and the desktop app takes it

Draft #373 (a computer without the Shield extension pairs with Shield on a phone by showing a code)
now uses `@provablehq/aleo-wallet-adapter-shield` 1.6.0 and `-core` 1.3.1, installed five days after
publication by Joshua's exception to the seven-day rule (OPS-04; `memory/decisions.md`), after a read
of the diff from 1.5.0 and a check that the installed files are the ones read. The rule and its CI
check are unchanged, so the pull request's age check passes only from 2026-11-27.

- On a computer the adapter now makes Shield's verified link, `https://connect.shield.app/connect#…`:
  a phone's camera opens an https link and the phone hands it only to the signed Shield app; every
  parameter, the pairing secret included, is after the `#`, which no browser sends to a server. On
  a phone the page keeps `shield://connect`, which it opens itself.
- `desktopPairingLink` accepts only that form: https, Shield's host and path, the parameters in the
  fragment and none in a query, an https origin; a custom-scheme link is refused on a computer.
- The desktop app declares the website's origin (`DECLARED_ORIGIN`), since its pages have none
  Shield could show, and takes the `pair` route: the pairing screen shows the code there, with no
  extension on offer. Its unfinished pairing, kept under the declared origin's own key, is forgotten
  on the next visit like the browser's.
- The pairing screen names the address Shield will show, and says what an out-of-date Shield does
  (opens a web page instead) and to update it.
- Merged main into #373 first: #354's signing-path check allows useShield only one way to build its
  wallet, so the "waiting for your phone" count moved into `checkedSend` (signatures are counted
  beside it).
- Docs: `DESKTOP_PAIRING.md` (1.6.0, what is still unverified and asked), the wallet README, T3 in
  the threat model, `apps/desktop/README.md` (status: reaches Shield by pairing with a phone, not yet
  tested on a device).
